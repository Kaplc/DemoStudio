# 游戏 UI 设计 - 尖锐边缘（失败模式）

## 安全区违规

### **Id**
safe-zone-violation
### **摘要**
关键 UI 元素放在电视安全区之外
### **严重级别**
critical
### **场景**
  电视上角落的血条被裁掉。某些显示器上看不到弹药计数器。
  任务文字超出屏幕边缘。玩家抱怨"我看不到我的血条"。
  
### **为什么**
  电视有过扫描——会裁掉边缘的 3-10%。不同厂商、型号和设置各不相同。
  与显示器不同，电视默认视频内容带安全边距。主机认证通常要求遵守安全区。
  玩家在自己的设备上玩不了，就会退款。
  
### **解决方案**
  # 安全区实现
  
  动作安全区（屏幕的 93%）：
  - 游戏玩法可以延伸到边缘
  - 移动元素可以到达这里
  
  标题安全区（屏幕的 90%）：
  - 所有静态 HUD 元素
  - 所有文字必须在此范围内
  - 所有交互元素
  
  实现：
  // 计算安全边距
  float safeMargin = screenWidth * 0.05f; // 每边 5% = 90% 安全区
  Rect safeArea = new Rect(
      safeMargin, safeMargin,
      screenWidth - safeMargin * 2,
      screenHeight - safeMargin * 2
  );
  
  // 将 HUD 元素定位在 safeArea 内
  healthBar.position = safeArea.topLeft + offset;
  
  必做：选项中提供安全区滑条（0-10%）
  主机默认保守的 5%，PC 默认 0%
  
### **症状**
  - 我看不到我的血条
  - 电视上文字被裁切
  - 主机认证失败
  - 玩家投诉因显示器而异
### **检测模式**
position:\s*(0|0px|0%)|anchor.*=.*0.*0|margin.*=.*0

## 手柄导航死路

### **Id**
controller-navigation-deadend
### **摘要**
菜单元素通过手柄导航无法到达或被困住
### **严重级别**
critical
### **场景**
  方向键选不到某些按钮。Tab 键能切换标签页但手柄不能。
  背包网格没有出口。确认弹窗不可聚焦。
  
### **为什么**
  手柄玩家实际上无法完成操作。游戏变得不可玩。
  这是"手柄不可玩"评价的头号原因。鼠标作为后备方案被加上，
  但纯手柄玩家（主机、Steam Deck）被困住了。
  
### **解决方案**
  # 手柄导航审查清单
  
  1. 焦点系统：
     - 每个交互元素都能获得焦点
     - 视觉焦点指示明显（不微妙）
     - 焦点指示在所有背景上都可见
  
  2. 导航：
     - 方向键逻辑移动焦点（不是乱跳）
     - 循环：行末 -> 下一行开头
     - 逃生路径：每个菜单都有清晰的"返回"路径
     - 标签页等价物：LB/RB 切换主要区块
  
  3. 测试流程：
     仅用手柄开始游戏：
     ✓ 主菜单 -> 选项 -> 所有子菜单 -> 返回
     ✓ 游戏 -> 暂停 -> 所有菜单项 -> 继续
     ✓ 背包 -> 所有格子 -> 装备 -> 退出
     ✓ 商店 -> 浏览 -> 购买 -> 退出
     ✓ 对话 -> 所有选项 -> 推进
  
  4. 要修复的焦点陷阱：
     - 模态弹窗必须困住焦点然后释放
     - 下拉菜单必须可导航、可关闭
     - 嵌套菜单需要清晰的返回行为
  
  // Unity 示例 - 确保导航
  button.navigation = new Navigation {
      mode = Navigation.Mode.Explicit,
      selectOnUp = upButton,
      selectOnDown = downButton,
      selectOnLeft = leftButton,
      selectOnRight = rightButton
  };
  
### **症状**
  - 手柄选不到这个
  - 焦点指示消失
  - 卡在子菜单里
  - 必须用鼠标才能继续
### **检测模式**


## 分辨率缩放失败

### **Id**
resolution-scaling-failure
### **摘要**
UI 只为一个分辨率设计，在其他分辨率下崩溃
### **严重级别**
critical
### **场景**
  UI 在 1080p 完美。在 4K 下元素变得微小。在 720p 下元素重叠。
  在超宽屏上 HUD 被拉伸或偏离中心。在 Steam Deck 上无法阅读。
  
### **为什么**
  现代游戏运行在从 720p 掌机到 8K 电视的显示器上。观看距离
  从 1 英尺（显示器）到 10 英尺（电视）不等。固定像素尺寸会变得
  微观或巨大。玩家不应该需要完美视力才能玩。
  
### **解决方案**
  # 分辨率无关的 UI 设计
  
  1. 参考分辨率：
     - 以 1080p（1920x1080）设计
     - 这是你的"100% 缩放"基准
  
  2. 缩放模式：
     - 随屏幕尺寸缩放（Unity Canvas Scaler）
     - 根据游戏类型匹配宽度或高度
     - 宽屏游戏：匹配高度（1080p 参考）
     - 竖屏游戏：匹配宽度
  
  3. UI 缩放选项：
     设置 -> UI 缩放：[50%] [75%] [100%] [125%] [150%] [200%]
     立即应用，保存偏好
     电视/主机默认更高
  
  4. 测试清单：
     □ 1280x720（Steam Deck、Switch）
     □ 1920x1080（基准）
     □ 2560x1440（游戏显示器）
     □ 3840x2160（4K 电视）
     □ 2560x1080（超宽屏）
     □ 3440x1440（超宽屏）
  
  5. 1080p 下的最小可读尺寸：
     - 正文：16px（从这里往上缩放）
     - 重要信息：24px+
     - 图标：最小 32x32px
  
  // Unity Canvas Scaler 设置
  canvasScaler.uiScaleMode = CanvasScaler.ScaleMode.ScaleWithScreenSize;
  canvasScaler.referenceResolution = new Vector2(1920, 1080);
  canvasScaler.matchWidthOrHeight = 1f; // 匹配高度
  
### **症状**
  - 4K 下 UI 微小
  - 低分辨率下元素重叠
  - Steam Deck 上文字不可读
  - 超宽屏 HUD 居中但两侧空白
### **检测模式**
fontSize:\s*[0-9]px|width:\s*[0-9]{3}px|height:\s*[0-9]{2}px

## 输入提示不匹配

### **Id**
input-prompt-mismatch
### **摘要**
对当前输入设备显示了错误的手柄按键图标
### **严重级别**
high
### **场景**
  用 PlayStation 手柄玩，却显示 Xbox 按键。键盘和手柄之间切换，
  提示不更新。"[按 A]"但我根本没有 A 键。
  
### **为什么**
  玩家不知道该按哪个键。教程被彻底破坏。
  造成困惑和客服工单。PlayStation 玩家把看到 Xbox 提示视为不尊重。
  专业游戏能无缝处理这个问题。
  
### **解决方案**
  # 输入提示系统
  
  1. 检测输入类型：
     - 追踪最后使用的输入设备
     - 任何不同设备的输入都切换提示
     - 小延迟（200ms）防止闪烁
  
  2. 需要的图标集：
     - Xbox（"通用手柄"默认）
     - PlayStation（检测 DualShock/DualSense）
     - Nintendo Switch（按键位置不同！）
     - 键盘 + 鼠标
     - 触控（移动端）
  
  3. 按键映射感知：
     // 不要硬编码 "[按 A]"
     string prompt = GetPromptForAction("confirm");
     // 返回 "[A]" 或 "[X]" 或 "[空格]" 等
  
     // 处理改键
     if (playerReboundConfirm) {
         prompt = GetBoundKeyPrompt("confirm");
     }
  
  4. 平台检测：
     // Unity 示例
     if (Gamepad.current is DualShockGamepad) {
         UsePlayStationIcons();
     } else if (Gamepad.current != null) {
         UseXboxIcons(); // 通用手柄默认
     } else {
         UseKeyboardIcons();
     }
  
  5. Steam Input 考虑：
     - Steam 可以重映射任何手柄
     - 可用时使用 Steam Input API 图标
     - 否则回退到检测到的类型
  
### **症状**
  - 显示按 A 但我在用 PlayStation
  - 用手柄时提示却显示键盘
  - 教程无法跟上
  - 切换输入时提示不更新
### **检测模式**
"Press A"|"Press X"|"Press \[A\]"

## 色盲失败

### **Id**
colorblind-failure
### **摘要**
关键信息仅通过颜色传达
### **严重级别**
critical
### **场景**
  敌人血条红色、友军血条绿色——色盲玩家无法区分。
  稀有度仅用颜色辉光表示。伤害类型用颜色但无图标。
  "红色代表停止"但 8% 的玩家看不清楚红色。
  
### **为什么**
  8% 的男性和 0.5% 的女性有色觉缺陷。红绿色盲
  （绿色盲/红色盲）最常见——恰好是游戏用来区分敌/友的颜色。
  如果没有补偿设计，游戏对数百万人来说真的不可玩。
  
### **解决方案**
  # 色盲友好设计
  
  1. 绝不只用颜色：
     - 敌人：红色 + 敌对图标 + "敌人"标签
     - 友军：蓝色 + 友好图标 + "友军"标签
     - 血量：红色条 + "HP"文字 + 当前/最大数值
  
  2. 形状区分：
     普通    | 危险   | 安全    | 中立
     圆形    | 三角  | 菱形    | 方形
     ●       | ▲     | ◆       | ■
  
  3. 无颜色的稀有度：
     普通：   素边框
     优秀：   单线边框
     稀有：   双线边框
     史诗：   边框 + 角饰
     传说：   全装饰边框
  
  4. 内置色盲模式：
     设置 -> 无障碍 -> 色盲模式：
     - 关闭
     - 绿色盲（红绿，最常见）
     - 红色盲（红绿，不同）
     - 蓝黄色盲（蓝黄，罕见）
  
     调整受影响的颜色：
     - 敌人红 -> 橙/粉
     - 友军绿 -> 蓝/青
     - 增加对比度
  
  5. 测试工具：
     - Coblis 色盲模拟器
     - Photoshop：视图 -> 校样设置 -> 色盲
     - Windows：轻松使用 -> 颜色滤镜
  
### **症状**
  - 分不清敌人和友军
  - 这件物品是什么稀有度？
  - 色盲用户的投诉
  - 无障碍认证失败
### **检测模式**


## 字号灾难

### **Id**
font-size-disaster
### **摘要**
文字在目标显示器上小到无法阅读
### **严重级别**
high
### **场景**
  在 27 英寸显示器上设计的，在沙发上对着电视无法阅读。提示框需要
  眯眼。战斗中的伤害数字难以辨认。物品描述需要放大镜。
  
### **为什么**
  观看距离差异巨大。24 英寸显示器 2 英尺外的 1080p
  和 50 英寸电视 10 英尺外的 1080p 完全不同。小字伤眼睛、
  排除了视力受损的玩家、造成无障碍失败。
  
### **解决方案**
  # 字号指南
  
  1. 1080p 下的最小尺寸（按比例缩放）：
     - 关键 HUD（血条、弹药）：24px+
     - 标准 UI 文字：18px
     - 次要信息：16px
     - 任何内容的最小值：14px
  
  2. 电视/主机倍率：
     基础 PC 尺寸 × 1.25 到 1.5 供电视观看
     或检测电视模式自动调整
  
  3. 字号选项：
     设置 -> 无障碍 -> 文字大小：
     [小] [普通] [大] [更大]
     按比例影响所有文字
  
  4. 字体选择很重要：
     - UI 用无衬线体（干净、可读）
     - 避免细字重（Light、Thin）
     - 测试小写字母可读性（a、e、c）
     - 高 x-height 字体小号更易读
  
  5. 可读性对比度：
     - 深色文字浅色背景：#333 配 #FFF
     - 浅色文字深色背景：#FFF 配 #222
     - 最低 4.5:1 对比度
     - 文字越小对比度要求越高
  
  6. 动态尺寸测试：
     □ 从 10 英尺外能读所有文字
     □ 角色移动时仍可读
     □ 激烈动作中清晰可辨
     □ 检查提示框/描述文字
  
### **症状**
  - 文字太小
  - 玩家前倾才能阅读
  - 游戏过程中眯眼
  - 要求文字大小选项
### **检测模式**
fontSize:\s*1[0-4](px)?|font-size:\s*1[0-4]px

## 晕动症触发

### **Id**
motion-sickness-trigger
### **摘要**
引起不适或前庭问题的 UI 动画
### **严重级别**
high
### **场景**
  UI 不断从屏幕外滑入。屏幕抖动应用到了 UI 元素上。
  菜单中的视差滚动。菜单转场的激进相机动画。
  
### **为什么**
  前庭障碍影响数百万人。过度动效导致恶心、头痛和迷失方向。
  有些玩家在物理上无法游玩过度动效的游戏。
  这是无障碍要求，不是偏好。
  
### **解决方案**
  # 动效安全 UI 设计
  
  1. 尊重系统偏好：
     // 检查操作系统级减少动效设置
     if (SystemPreferences.ReducedMotion) {
         DisableUIAnimations();
         UseInstantTransitions();
     }
  
  2. 游戏内选项：
     设置 -> 无障碍 -> 减少动效：[开/关]
     影响：
     - 屏幕抖动强度（独立滑条）
     - UI 转场动画
     - 菜单中的相机运动
     - 视差效果
  
  3. 安全与有问题的动画：
     安全：
     - 淡入/淡出（仅透明度）
     - 从 95% 缩放到 100%（轻微）
     - 颜色过渡
     - 进度条填充
  
     有问题：
     - 从屏幕外滑入
     - 弹跳/弹性效果
     - 屏幕抖动
     - 旋转
     - 视差滚动
     - 缩放动画
  
  4. 需要动效时：
     - 时长小于 200ms
     - 仅缓出（先快后慢）
     - 小移动距离
     - 单一方向（不要之字形）
  
  5. 屏幕抖动特例：
     设置 -> 相机抖动：[关] [低] [中] [高]
     绝不对 UI 施加抖动，只作用于世界
  
### **症状**
  - 恶心报告
  - 动画太多
  - 要求减少动效
  - 短时间游玩后退出
### **检测模式**
animation-duration:\s*[5-9][0-9]{2}ms|animation-duration:\s*[1-9]s

## 触控目标过小

### **Id**
touch-target-too-small
### **摘要**
交互元素太小，无法可靠触控或手柄选择
### **严重级别**
high
### **场景**
  移动端移植版按钮很小。关闭按钮只有 16x16 像素。背包
  格子需要外科手术级精度。手柄选择框比可见元素还小。
  
### **为什么**
  手指不精确。触摸屏上的拇指更差。手柄摇杆导航需要宽裕的选择区域。
  小目标导致误触、挫败感，让游戏感觉坏了。
  Apple 和 Google 制定指南是有原因的。
  
### **解决方案**
  # 触控与选择目标尺寸
  
  1. 最小尺寸：
     - Apple：最小 44x44pt
     - Google：最小 48x48dp
     - 游戏 UI：1080p 下 48x48 像素（往上缩放）
     - 宽裕：重要操作 56x56+
  
  2. 视觉区 vs 触控区：
     图标可以 24x24，但触控区必须是 48x48
     ┌────────────────┐
     │   ┌────────┐   │
     │   │ [icon] │   │ <- 视觉 24x24
     │   └────────┘   │
     └────────────────┘  <- 触控 48x48
  
  3. 目标间距：
     可触控区域之间最小 8px 间隙
     防止意外点选相邻目标
  
  4. 手柄选择：
     - 选择高亮大于元素本身
     - 方向键导航吸附到逻辑网格
     - 可见的焦点指示，不只是颜色
  
  5. 实现：
     // Unity 带隐形扩大命中区的 Button
     [RequireComponent(typeof(Image))]
     public class TouchExpander : MonoBehaviour {
         public void OnValidate() {
             GetComponent<Image>().alphaHitTestMinimumThreshold = 0f;
             // 将 RectTransform 扩展到可见内容之外
         }
     }
  
  6. 测试协议：
     - 用拇指测试，不用触控笔/鼠标
     - 运动中测试（模拟游戏）
     - 单手测试（竖屏移动端）
     - 仅用手柄测试
  
### **症状**
  - 误触和错误选择
  - 按钮太小
  - 手柄导航感觉不精确
  - 移动端玩家挣扎
### **检测模式**
width:\s*[0-3][0-9]px|height:\s*[0-3][0-9]px|size.*=.*[0-3][0-9]

## HUD 遮挡游戏画面

### **Id**
hud-obscures-gameplay
### **摘要**
UI 元素阻挡了关键游戏画面的可见性
### **严重级别**
high
### **场景**
  血条放在敌人刷新的位置上方。小地图盖住了狙击手躲藏的角落。
  对话方块遮住玩家角色。任务追踪器挡住了地上的战利品。
  
### **为什么**
  玩家死于看不见的东西。本应帮助他们的信息
  实际上伤害了他们。屏幕空间很宝贵——每个 UI 元素
  都在消耗可见性。这打破了公平竞技的根本契约。
  
### **解决方案**
  # HUD 定位原则
  
  1. 关键游戏区域：
     - 中央：准星区域必须干净
     - 玩家角色：必须可见
     - 即时威胁区：通常在中央/前方
     - 交互区：玩家注视的地方
  
  2. 安全的 HUD 位置：
     ┌───────────────────────────────────┐
     │ [血条]          [小地图] │ <- 角落
     │                             │
     │                             │
     │                             │ <- 中央是神圣的
     │                             │
     │ [技能]    [任务目标] │ <- 底部角落
     └───────────────────────────────────┘
  
  3. 动态隐藏：
     - 战斗模式：隐藏非必要 UI
     - 电影模式：隐藏所有 UI
     - 拍照模式：完全移除 UI
     - 开镜瞄准：清空准星区域
  
  4. 非关键 UI 用透明度：
     - 小地图：60-80% 不透明度
     - 任务追踪器：70% 不透明度
     - 提示框背景：半透明
  
  5. 玩家控制：
     设置 -> HUD 位置：[预设/自定义]
     允许重新定位单个元素
     按元素保存不透明度偏好
  
  6. 特例 - 对话：
     - 放在底部并带说话人头像
     - 绝不放玩家角色上方
     - 提供半透明或不透明选项
     - 无障碍自动推进选项
  
### **症状**
  - 敌人从小地图后面冒出来
  - 看不到我的角色
  - 玩家关掉有用的 UI
  - 死亡归咎于 UI 遮挡威胁
### **检测模式**


## 文字无描边或阴影

### **Id**
no-text-outline-or-shadow
### **摘要**
没有描边/阴影的文字在多变背景上无法阅读
### **严重级别**
high
### **场景**
  亮天空上的白色文字——看不见。阴影里的深色文字——看不见。
  火焰特效上的血量数字无法阅读。伤害数字迷失在技能粒子中。
  
### **为什么**
  游戏有动态背景。这一帧可读的内容下一帧就看不见。
  UI 文字无论背后是什么都必须清晰可辨。
  这是最常见的 HUD 可读性问题，也最容易修复。
  
### **解决方案**
  # 文字可读性技巧
  
  1. 文字描边（最佳）：
     2px 对比色描边
     白色文字 -> 黑色描边
     黑色文字 -> 白色描边
     彩色文字 -> 深色描边
  
  2. 投影（好）：
     2-4px 偏移，50% 不透明度
     方向：右下（光源来自左上）
     模糊：0-2px（锐利优于模糊）
  
  3. 背景面板（最安全）：
     半透明深色背景
     文字后 20-40% 黑色
     一致的容器方案
  
  4. 组合方案（推荐）：
     文字 + 1px 描边 + 轻微阴影 + 面板
     任何情况下都可读
  
  5. 绝不：
     - 无描边的细字体
     - 低对比度（灰对灰）
     - 依赖背景保持一致
  
  // CSS 示例
  .hud-text {
      color: white;
      text-shadow:
          -2px -2px 0 black,
           2px -2px 0 black,
          -2px  2px 0 black,
           2px  2px 0 black,
          0 2px 4px rgba(0,0,0,0.5);
  }
  
  // Unity TextMeshPro
  Set Outline Width: 0.2
  Set Outline Color: Black
  Enable Underlay for shadow effect
  
### **症状**
  - 读不了数字
  - 某些背景上文字消失
  - 背景变化时 HUD 元素"闪烁"
  - 截图显示不可读的 UI
### **检测模式**
text-shadow:\s*none|textShadow:\s*"none"

## 按键行为不一致

### **Id**
inconsistent-button-behavior
### **摘要**
同一按键在不同屏幕上做不同的事
### **严重级别**
high
### **场景**
  "B"在背包里返回，但在暂停菜单里关闭游戏。"Y"在这里确认，
  在那里却取消。确认/取消的位置在菜单间互换。
  
### **为什么**
  玩家建立肌肉记忆。不一致导致他们意外
  关闭游戏、删除存档或做出错误购买。每个意外
  都在破坏信任。这是千刀万剐式的死亡。
  
### **解决方案**
  # 一致的按键映射
  
  1. 通用映射（永不改变）：
     A/叉：确认、选择、推进
     B/圆圈：返回、取消、关闭
     Start：暂停、菜单
     Select：地图、次要菜单
  
  2. 上下文映射（显示提示）：
     Y/三角：上下文动作 1（检视、拾取）
     X/方块：上下文动作 2（丢弃、使用）
     肩键：切换标签页、循环
     扳机键：翻页、缩放
  
  3. 位置一致性：
     - "返回"在菜单中始终同一位置
     - "确认"始终同一位置
     - 排序一致（接受-取消，而非取消-接受）
  
  4. 危险操作：
     - 要求长按，而非轻按
     - 与相邻操作使用不同按键
     - 确认对话框
     - 删除/退出要"你确定吗？"
  
  5. 记录并显示：
     - 屏幕上的按键图例
     - 提示随上下文更新
     - 设置显示完整映射
  
  6. 平台惯例：
     Xbox：A=是，B=否
     PlayStation（日本）：圆圈=是，叉=否
     PlayStation（西方）：叉=是，圆圈=否
     设置中支持两种惯例
  
### **症状**
  - 我不小心退出了游戏
  - B 应该返回，不是关闭
  - 玩家被变化的行为搞糊涂
  - 频繁执行错误操作
### **检测模式**


## 不显示键盘快捷键

### **Id**
no-keyboard-shortcut-display
### **摘要**
键盘操作存在但没有展示，或改键后提示失效
### **严重级别**
medium
### **场景**
  "还有键盘快捷键？""我改了 WASD 但提示还是显示 WASD。"
  Alt+F4 无警告直接关闭游戏。快捷键只藏在提示框脚注里。
  
### **为什么**
  玩家发现不了有用的快捷键。改键让提示变成谎言。
  高级用户对隐藏功能感到恼火。新玩家错过效率。
  
### **解决方案**
  # 键盘快捷键可见性
  
  1. 显示绑定键，而非默认键：
     // 错误
     prompt = "Press SPACE to jump";
  
     // 正确
     string jumpKey = GetBoundKey("Jump");
     prompt = $"Press {jumpKey} to jump";
  
  2. 提示框快捷键：
     背包（I）
     地图（M）
     任务日志（J）
     显示绑定键，不硬编码
  
  3. 键位图例选项：
     设置 -> 操作 -> 显示键位：开/关
     切换键位图例浮层
  
  4. 改键感知：
     - 改键时更新所有提示
     - 改键时显示冲突
     - "恢复默认"选项
  
  5. Alt+F4 处理：
     - 要么禁用，要么显示保存确认
     - 不丢失未保存进度
     - 或明确支持为"快速退出"
  
  6. 隐藏快捷键文档：
     操作界面列出所有快捷键
     包含"高级"区块
     量大时可搜索
  
### **症状**
  - 不知道有快捷键
  - 改键后提示显示错误按键
  - 玩家因 Alt+F4 丢失进度
  - 这个键是干什么的？
### **检测模式**
"Press [A-Z]"|"Press Space"|"Press Enter"
