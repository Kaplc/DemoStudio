# 暖流计划 · 供应链重构方案（月球 H3 稳定运回 + 船队设计工坊）

> 状态：**已实施（一期 + 二期全量，2026-09-13）**——实施记录见文末 §14 与 [implementation.md](./implementation.md)
> 参考文档：《火箭工坊》完整设计方案（休闲拼装火箭游戏的模块化设计模式）
> 关联文档：[implementation.md](./implementation.md)（现有实现全量记录）

---

## 0. 一句话定位

把《暖流计划》的核心问句从"地球堆心别凉"重定向为：**你在月球的产量 × 你的船队设计 × 你的线路冗余，能否在耀斑和引力窗口的干扰下，在地球储量耗光之前把 H3 稳定运回来。**

船队设计参考《火箭工坊》的模块化模式：**船型即底盘，底盘决定槽位；部件少而精，每个部件对应一个玩家能理解的决策；自动计算 + 试航预估 + 运力反推；任务逼取舍。**

---

## 1. 现状诊断（为什么要改）

### 1.1 矿建直采架空了运输系统

`MiningComponent.tickMines`（MiningComponent.ts:106-107）矿建产出 `s.earthH3 += n` **直入地球储备**——不走航线、不派船、不受耀斑威胁，天生"稳定"。而月球一趟航线净赚约 160 吨，要跑腿、烧油、怕冻毁。

玩家理性策略 = 全投矿建，航线系统退化成教程摆设。这与主题拧着：星图、拖线、耀斑、引力窗口、中转站、船坞——全部系统的存在意义都建立在"运输是核心"上，2026-09-12 加的全息勘探恰好把"运输"这一环短路了。

### 1.2 供需数量级断裂（比 1.1 更深）

| 端 | 现状 | 量级 |
|---|---|---|
| 需求 | `level_burn` 指数曲线 2^l：Lv8（Act2 门槛）= 256/s，Lv16（Act3 门槛）= 65536/s | 指数 |
| 供应 | 月球一船线净 ≈10/s/船，3 船 ≈30/s；木卫二 12/s；火星 16.6/s；矿建直采 0.5~1.4/s | 线性封顶 ~50/s |

**供应封顶与需求差 5 个数量级**。中后期理性策略是"永远别升环"（等级由建设流派生，可停建冻结）——环升级实际是自杀按钮，"稳定运回"无从谈起。中后期经济必然崩盘，长期断环。

### 1.3 结论

不是加新玩法，而是把游戏拉回它本来该有的问句。两处手术：
1. **把"产量"与"到手量"拆开**（堆场耦合）——让运输重新成为必经之路；
2. **重订供需曲线**——让每个等级都落在"当级运力可匹配"的量级。

## 2. 设计目标

- 核心张力 = 供应链的**稳定性**：产量、运力、到手量三层咬合，玩家管理的是一条会断的流水线，不是一堆孤立数字。
- 船队设计参考《火箭工坊》：槽位化拼装、指标自动计算、失败原因直给、没有唯一最优解。
- 倒计时开局：地球初始储量是旧时代储备，烧完前必须把月球线跑通——前期紧迫感自带。
- 保留现有骨架不推翻：堆心温度、耀斑、引力窗口、中转站、护盾、研究点数、三幕结构全部沿用，只重新接线。
- 旧档可进（存档迁移规则见 §12）。

---

## 3. 新核心循环

```
探查矿点 → 建矿建（产量层）→ 造船/配槽（运力层）→ 拖线运回（到手层）
   → 看试航卡/收支曲线 → 耀斑/引力窗口扰动 → 扩环（需求抬台阶）→ 被迫扩供应链 → 循环
```

与《火箭工坊》"接任务→选型号→拖部件→看指标→发射→结算"同构，差别在于 warm 的"发射"是持续运输流，"任务"是三幕供应链接力。

## 4. 地球侧：储量倒计时 + 本地产线

### 4.1 储量倒计时（已有骨架，显性化）

- `earthH3Start: 800` 已存在；Lv1 焚烧 2/s → **开局自带 400 秒倒计时**。教程期（建矿 12s + 造船 15s + 画线）约 60s，第一条月球线即可跑通，压力刚好。
- 堆心温度机制 = "耗光之后"的二次缓冲（烧空 → 断环降温 30s → 归零才败），沿用不动。
- 开局叙事化：800 吨定位为"旧文明储备 / 最后的燃料库"，HUD 强化倒计时感（现有 dangerReserveSeconds 告警保留）。

### 4.2 本地产线（可选件，待拍板 §13.2）

一条 0.5/s 的"氘氚备用堆"（叙事：最后一座老聚变堆）：
- 作用：新手期保底、断环期喘息、心理模型与倒计时互补（储量 = 倒计时，产线 = 底线）；
- 量级：恒为一台采矿机水平，永远当不了主角；
- 实现：`SimState` 加 `earthBaseYield: number`（默认 0，配置表可开），EconomyComponent tick 内加收入项。

## 5. 星球侧：堆场耦合（三层模型）

### 5.1 机制

**矿建产出不再直入 earthH3，落在该天体的本地堆场，必须由航线运回才到手。**

```
矿建（产量层）→ 星球堆场（缓冲层）→ 航线船队（运力层）→ 地球储备（到手层）→ 焚烧/建设/研究（消耗层）
```

- `SimState` 加 `starStock: Record<StarId, number>`（月球/木卫二/火星各一），堆场上限 per-star 表驱动；
- `tickMines` 产出改入 `starStock[star]`，**堆满停产**（激励持续维持运力）；
- 正向航线装货从"凭空满载"（TransportComponent.ts:373 `starLoad(...)` 直接给满）改为**从堆场扣取，装不满就少装**；
- 到手量 = min(产量, 运力吞吐, 堆场缓冲)——三层任何一层成为瓶颈，玩家都能从 HUD 看出来（§8.2）。

### 5.2 设计含义

- 矿建与航线从**竞争**变**上下游**：钱投矿建还是投船，成为真实的资本分配决策；
- "堆满停产"让供应链中断第一次成为真实可能，堆心温度机制天然就是断流检测器；
- 现有卡 `moonLoadAdd`（月球满载 +50）语义迁移为"月球矿建产出加成"（产量层加成）。

### 5.3 数值草案（待模拟验证）

| 项 | 现值 | 草案 | 说明 |
|---|---|---|---|
| 采矿机 yieldPerS | 0.5/s | 2.5/s | 产量层主角化 |
| 冶炼厂 yieldPerS | 1.4/s | 7/s | 高投入高产出定位不变 |
| 月球矿点数 | （mineral_deposit 表现值） | 4~5 | 满开发 ≈ 26/s 基础 |
| 木卫二 / 火星矿点数 | — | 5~6 / 6~7 | 逐幕产量台阶上行 |
| 堆场上限（月球/木卫二/火星） | — | 800 / 2000 / 4000 | ≈ 2~3 船满载缓冲 |
| 产量层成长杠杆 | — | 环建筑"采矿馈能" +5%/座、研究线乘区 | 与运力层并行升级 |

## 6. 经济重订：供需咬合

### 6.1 焚烧曲线重订

`level_burn.table.json` 从指数 2^l 改为多项式（**只改表，代码零改动**，B.levelBurn 已从表读）：

```
burn(l) = round(2 + 5.3 × (l−1)^1.23)
```

| 等级 | Lv1 | Lv4 | Lv8 | Lv12 | Lv16 | Lv20 | Lv25 |
|---|---|---|---|---|---|---|---|
| 焚烧 吨/s | 2 | 22 | 60 | 103 | 150 | 200 | 266 |

形状意图：**前期陡**（每升一级都逼一次扩运力），**后期缓**（靠多线叠加与大星运力消化）。供应端三级接力（§6.3）逐幕撑起新台阶。

### 6.2 咬合校验规则（比具体数字更重要）

**每级"理论满编净流入" ≥ 该级总需求 × 1.4**（40% 余量给研究计费、建设灌入、维护费与利润缓冲）。

- 总需求 = 焚烧 + 研究点计费（封顶 25 点 × 3 = 75/s）+ 建设灌入（~4/s）+ 舰队维护（封顶 5/s）≈ 焚烧 + 85/s 封顶
- Lv25 校验：(266 + 85) × 1.4 ≈ **490/s**，供应端上限估算见 §6.3，落在 400~600/s 区间（含超导馈线堆叠杠杆），达标但接近满编——Act3 的紧张感来自"接近极限才能满足"。
- 此校验固化为单测（`tests/warm_supply_match.test.ts`）：改动 level_burn / ship_cap / stars 任一表自动重算。

### 6.3 供应端三级接力（现有数值即够用）

| 星 | 单船净吞吐（标准/优化配） | 放量来源 |
|---|---|---|
| 月球 dist=1 | 10/s / 22.5/s（重载+货舱+泵） | ship_cap Lv4=4 艘、Lv6=5 艘 |
| 木卫二 dist=3 | 12/s / 30/s | Act2 解锁，600 载 |
| 火星 dist=6 | 16.6/s / 40/s | Act3 解锁，1500 载 |

后期杠杆（既有）：超导馈线 loadMult +3%/座 × 25 座 = +75% 载量；中转链减空驶（§8.1）。**12 艘满配多线 ≈ 400~480/s**，与 §6.2 咬合。

### 6.4 幕内稳态算例（Act1，验证开局体验）

- 开局 800 吨，Lv1 烧 2/s，教程 60s 后第一条月球线 +10/s → 净流入 +8/s，库存缓涨；
- 升到 Lv4（22/s）需 2~3 条线或 1 条优化线；Lv6（46/s）需 4 艘船（ship_cap Lv6=5 正好放开）；
- 每次升环 = 需求台阶 = 被迫在"下一艘船 / 下一座矿 / 攒缓冲"之间做现金流决策——**扩张→紧缩循环自动形成**。

## 7. 船队设计工坊（参考《火箭工坊》模块映射）

### 7.1 映射总表

| 《火箭工坊》 | warm 移植 | 取舍 |

| 型号 = 底盘，决定槽位数量与类型 | 船型 hull 升级槽位制（§7.2） | **直接搬**（allowed 白名单升级为槽位类型） |
| 部件 6 类、每类 2~5 型号 | 模块按槽位类型归口，每类出 2 档 | **改造**：槽位制先行，分档二期 |
| 性能面板 6 指标自动算 | 试航卡（§7.3） | **直接搬思想** |
| 运力反推（减载荷到 Δv 刚好） | 线路反推：目标净流入 → 需几艘什么船（§7.4） | **改造**：反推对象从载荷质量变船数 |
| 拖拽装配 + 绿/灰/红兼容 | 造船面板槽位化交互（§7.5） | **直接搬** |
| 失败原因直给表 | 运输失败诊断（§7.6） | **直接搬思想** |
| 一键推荐配置 | 自动配船建议 | 二期 |
| 蓝图保存/读取 | 船型设计模板 | 二期 |
| 发射 2D 动画 | — | **不搬**（星图光点运输流已是"发射过程"） |
| 排行榜 | — | **不搬**（单机 PVE） |
| 科技树 | 现有研究点数制 | 已有，不动 |

### 7.2 槽位化船型（表结构改造）

`ship_hull.table.json` 加 `slots` 字段（替代 `allowed` 白名单），`ship_module.table.json` 加 `slotType` 字段：

```jsonc
// ship_hull（草案）
"standard": { "slots": { "cargo": 1, "tank": 1, "engine": 1, "utility": 1 } },   // 4 槽全能
"hauler":   { "slots": { "cargo": 2, "tank": 1 } },                              // 3 槽装货专精
"courier":  { "slots": { "engine": 2, "tank": 1 } },                             // 3 槽提速专精
"guardian": { "slots": { "cargo": 1, "tank": 1 }, "innate": ["anti_freeze"] }    // 2 槽+内置防冻

// ship_module 补 slotType：cargo_pod→cargo / aux_tank→tank / ion_engine→engine / pump,heater→utility
```

设计含义（同《火箭工坊》"型号取舍"）：standard 玩家自己拼"2 货舱还是 1 货舱 1 油箱"的取舍；专用船型槽少但乘区强。表驱动，加新船型/新模块只改表。

> **2026-09-13 三部位改版追记（用户需求：槽位 = 荷载/燃料/引擎 + 荷载可单独设计）**：
> 槽型更名 `cargo→payload`、`tank→fuel`，功能槽 `utility` 下线（泵/加热器改占荷载槽）；现行表：
>
> ```
> "standard": { "slots": { "payload": 1, "fuel": 1, "engine": 1 } },   // 3 槽全能
> "hauler":   { "slots": { "payload": 2, "fuel": 1 } },                // 双荷载专精
> "courier":  { "slots": { "engine": 2, "fuel": 1 } },                 // 双引擎专精
> "guardian": { "slots": { "payload": 1, "fuel": 1 }, "innate": ["anti_freeze"] }
> ```
>
> 荷载设计工坊：主体（cargo_s/pod/x，payloadRole='chassis'）+ 舱内附件（pump_s/pump/heater，'attachment'）
> 合成一件自定义荷载（造价 ×1.15 组装溢价，占 1 荷载槽，旁路 allowed 只受槽位闸）；
> `SimState.payloadDesigns`（uid pdN 不复用）随档走，动态注册表 `setDynamicShipModules` 投影到 `shipModuleDefOf`。
> 详见 doc/game/玩家设计权扩展方案-V1.md 追记章。

### 7.3 试航卡（性能面板 → 试航预估）

造船面板选型即时自动计算（对应《火箭工坊》六指标）：

| warm 试航卡指标 | 定义 | 对应火箭工坊 |
|---|---|---|
| 单线吞吐率 | 满载 ÷ 轮时（吨/s） | 推重比 TWR |
| 单趟净赚 | 满载 − 油耗（吨） | Δv |
| 可装满吗 | 该线堆场产出 vs 船吞量 | 体积 |
| 冗余度 | 该线船数 ÷ 满足需求所需船数 | 回收（冗余 = 保险） |
| 总成本 | 造价 + 维护费增量 | 预算 |
| 风险面 | 耀斑暴露时长、护盾覆盖、窗口折价 | 可靠性 |

### 7.4 线路反推（运力反推的 warm 版）

输入：目标净流入（如"补上 Lv8 焚烧缺口 30/s"）。反推输出：该星需要几艘"当前选中配置"的船，或给出"重载 ×2 优于标准 ×3"的对比。实现为纯函数（读 stars 表 + 船乘区 + legSeconds），挂在试航卡旁。

### 7.5 装配交互

造船面板改槽位制：左侧模块库按槽位类型分组，中间船型槽位图，拖拽兼容性三色（绿色可放 / 灰色未解锁 / 红色槽型不符）。沿用现有 widget 资产风（ring_panel 深蓝青描边），不引新风格。

### 7.6 运输失败诊断表（失败原因直给）

| 失败表现 | 原因 | 提示（hint 文案） |
|---|---|---|
| 船在星球空转等货 | 堆场枯竭（产量层瓶颈） | 多建矿建，或换冶炼厂 |
| 堆场满仓停产 | 运力层瓶颈 | 加船，或开辟第二条线 |
| 耀斑冻毁 | 无护盾覆盖 | 造护盾 / 装防冻 / 预警期改待命 |
| 到港净货为负 | 油耗吞货 | 装副油箱，或等引力窗口出发 |
| 地球库存见底断环 | 供应 < 需求 | 看收支曲线：缺口在产量还是运力 |

### 7.7 二期件

一键推荐配置（自动填一个能过关但非最优的船）；船型设计模板（保存/读取/复用）； medals 式线路评级（满载率/低成本/零冻毁）。

## 8. 运输线路设计

### 8.1 中转链（二期，最大的一块空地）

正向 H3 线路支持「星球 → 中转站 → 地球」多段路由（现在中转站只能接反向补给线，TransportComponent.ts:72 直接拒绝其他组合）。中转站三重身份：
- 耀斑避难港（shelter 从"就近改道"升级为真中途港）；
- 中途缓冲库存（供应链弹性 = 花 H3 买的保险）；
- 拓扑决策：建不建、建在哪，玩家自己算账。

### 8.2 HUD 反馈（一期）

- **收支曲线**：焚烧+计费+维护 vs 到手量，实时看出"攒缓冲"还是"烧家底"；
- **堆场水位**：星图星球图标旁水位条（满仓=红色停产警示）；
- 三层瓶颈指示：产量 / 运力 / 缓冲哪层亮红灯，对应 §7.6 诊断。

### 14.3 实施中的坑（后续维护注意）

1. **vite 对 asset/config/*.json 的 transform 缓存不随内容变化自动失效**（静态 serve 是新内容、`?import` 模块是旧内容）——python 脚本批量改表后必须 `touch` 触发 watcher，否则运行时吃旧表（表现为「单测绿、e2e 跑旧数值」）。
2. **单测环境 ConfigRegistry 无表**：断言只认 B 代码默认值——改表必须同步 B 默认（双写测试锁口径）。
3. **e2e 卸货断言时机**：装卸状态机 load→flying→unloading→complete 需三段 tick（load+0.1 / legTime+0.1 / unload+0.2），两段会漏卸货；且 completeUnload 后 ship.cargo 清零，断言值须先取。
4. **hauler 槽位设计回修**：初版 slots={cargo:2,tank:1} 把 allowed 里的 pump（utility 槽）挤掉，回修补 utility:1——slots 与 allowed 双闸必须同审。
