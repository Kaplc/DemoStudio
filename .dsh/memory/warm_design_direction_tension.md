# warm 设计方向：以博弈感为准绳

**规则：** 2026-09-12 用户评估 warm"没什么博弈感"——后续 warm 的设计/开发提案，以"是否增加策略张力（有来有回的对抗 + 有代价的取舍）"为首要筛选标准；已向用户提交的候选方向：太阳活动周期+预报系统（首推，对手=太阳）、稀缺压贴零、矿脉枯竭节拍、环建筑/卡池构筑取舍、耀斑抉择卡。太阳活动周期方案已落盘 `doc/game/太阳活动周期方案-V1.md`（待实施）。同日用户定调 V1.1 两要素：参考冰汽时代暴风雪的右上角读条（风暴时刻提前排定、读条常驻可信）+ 每个行星系单独计算（分区=地月/木星/火星系，随产线逐幕解锁，分区配置表驱动、架构兼容未来多恒星系）。

**2026-09-27 延伸：** 用户把深度诉求细化到核心机制——"直接连线也没什么深度"（画线连完即决策归零、线的路径与线间关系不参与结算）。设计共识：深度来自约束/路径/流量/时序，不来自画线手势。**同日用户拍板先做两项并已实装**（方案规格 `doc/game/枢纽补给与港口泊位方案-V1.md`，单测 tests/warmPortHub.test.ts + e2e port_hub.spec.ts）：①借站补给——forward 星→地线途经中转站 300px 内往返油耗 ×0.8（放置位即策略）；②地球港泊位 portBerths=2——卸货占泊/满泊 waitPort FIFO 排队，N 船≠N 倍收益。轨道设计模块（KSP 式）已评估为不做：违反"拖拽画线是唯一核心操作"定案，属工程作业非策略决策。剩余候选（弧线穿罩/线级优先级/装矿速率/折扣需站内有货）按试玩反馈排队。
