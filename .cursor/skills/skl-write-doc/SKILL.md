# 编写功能工作流程文档

## 何时使用
- 用户要求新建/重写某个子系统的设计文档
- 给一个已有但没文档的功能补文档
- 某子系统发生重大重构后更新对应文档

> ⚠️ 本 skill **只写"系统/功能工作流"类文档**，不写资产创建（用 `create-*-asset` skill）

## 建立文档前的强制步骤

1. **先读 `doc/README.md`**：确认文件落在 `doc/engine/` 还是 `doc/editor/`
2. **复用现有文档风格**：打开同目录下现有文档作模板
3. **用代码事实校验**：通过 `read`/`grep` 读源码确认接口签名、类名、字段
4. **不要重复造轮子**：先用 `grep` 查 `doc/` 下是否已有重叠文档

## 文档统一结构（必须照此顺序）

```
# <功能中文名>（<English Name>）

## 1. 概述
- 功能定位、关键角色、责任表、与相邻功能的边界

## 2. 核心类 / 模块
| 类 / 模块 | 说明 |
表格化，说明列写职责

## 3. 使用方法
- 入口 API：函数签名 + 调用示例
- 触发时机 + 使用前提

## 4. 工作流程
- 4.1 主流程：mermaid flowchart
- 4.2 分阶段说明
- 4.3 设计要点

## 5. 边界条件
| 条件 | 行为/后果 | 处理方式 |

## 6. 依赖关系 / 注册机制
## 7. （可选）踩坑记录
```

## 关键规则

- **§3 使用方法、§4 工作流程、§5 边界条件 是必写核心**
- 章节顺序与编号不可变
- 代码位置必须写（文档头部和 §2 表都写明 `src/...`）
- 跨文档一律相对路径链接
- 不出现"可能"、"大概"、"应该"

## 建立新文档后的强制动作

**写完文档后必须更新 `doc/README.md`**：
- 在对应分类表格下一行追加
- 格式：`| [文件](./路径.md) | 一句话说明 |`

## 完成检查清单

- [ ] 文件落在了 `doc/engine/` 或 `doc/editor/`
- [ ] 头部含：一句话定位 + `src/...` + 至少 1 条相关文档链接
- [ ] §3/§4/§5 三个核心章节完整
- [ ] 所有类名/方法名在源码里 grep 得到
- [ ] `doc/README.md` 的对应表格已追加
