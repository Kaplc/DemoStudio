# 编写功能工作流程文档

> ⚠️ 本 skill **只写"系统/功能工作流"类文档**，不写资产创建（用 `create-*-asset` skill）

## 何时使用
- 用户要求新建/重写某个子系统的设计文档
- 给一个已有但没文档的功能补文档
- 某子系统发生重大重构后更新对应文档

## 建立文档前的强制步骤

1. **先读 `doc/README.md`**：确认落 `doc/engine/` 还是 `doc/editor/`（编辑器文档再按主题落二级子目录 `core/`、`blueprint/`、`asset/`、`ui/`、`integration/`，见 README.md §3）
2. **复用现有文档风格**：打开同目录任意现有文档作模板，照抄章节标题顺序与语气，**不要自创章节顺序**
3. **用代码事实校验**：每个类名/方法名/字段名必须能在源码里 grep 到，禁止凭印象描述 API（DemoStudio 命名常反直觉）
4. **不要重复造轮子**：先 grep `doc/` 查重叠文档，已有内容用相对链接引用

## 写作第一原则：写给「十分钟要上手的新人」

**旧范式（禁止再写）**：概述 → 核心类表格 → 使用方法 → 工作流程 → 边界条件。新人读完只得一堆 API 名字。

**新范式（照此写）**：
1. 开篇三问（头部 `>` 块）：一句话定位 / 什么时候会用到你 / 代码位置
2. 先记住这几个文件：2~4 个文件 + 「你要改它的场景」列
3. 流程讲解 = 贴真实源码 + 逐段白话讲解（可裁剪不得改写）
4. 关键方法速查表：方法 | 位置(文件:行号) | 干什么 | 注意
5. 流程影响 = 上游/下游表 + 相关文档链接
6. 踩坑清单：编号条目「现象 → 原因 → 规则」，只写真踩过的
7. 边界条件表格收尾

**章节骨架**（完整版见权威 SKILL：`.github/skills/skl-write-doc/SKILL.md` §3.2）：

```
# <功能中文名>（<English Name>）
> 一句话定位 / 什么时候会用到你 / 代码位置
## 1. 先记住这几个文件
## 2. <主流程名>：从 <起点> 到 <终点>   （mermaid + 逐段贴码讲解）
## 3. <第二条主链路>是怎么流进来的
## 4. 关键方法速查
## 5. 流程影响：上游 / 下游
## 6. 踩坑清单
## 7. 边界条件
```

## 关键规则

- 代码位置必须写（文档头部和文件表都写明 `src/...`）
- 跨文档一律相对路径链接
- 不出现"可能"、"大概"、"应该"

## 完成检查清单

- [ ] 文件落在正确目录（README.md §3 定位）
- [ ] 头部三问齐 + `src/...` 路径 + 相关文档链接
- [ ] 流程讲解有真实源码片段（不是纯文字转述）
- [ ] 所有类名/方法名在源码里 grep 得到
- [ ] `doc/README.md` 对应表格已更新
