# 枢纽补给与港口泊位方案-V1

> **一句话定位**：把两项"真实星际航线设计"原则落进《暖流计划》核心循环——**中转站升格补给枢纽**（星→地航线途经中转站即油耗打折，"远程货源借月球/中转站补给接力"）+ **地球港泊位有限**（卸货占泊、满泊排队，N 船 ≠ N 倍收益）。二者都不新增资源、不碰"拖拽画线是唯一核心操作"定案：玩家依旧只画线、派船、放建筑，但每条线的选择从 1 个变 4 个（连不连、怎么绕、派几艘、何时靠泊）。

> 2026-09-27 用户从"直接连线没什么深度"出发拍板先做这两项（另三项候选——弧线穿罩、线级优先级、中继导航塔——见文末待确认）。设计准绳沿用 2026-09-12"是否增加策略张力"：泊位把"堆船"从线性增益变成调度题，借站把"建筑放置"从被动Buff变成主动拓扑决策。

## 1. 借站补给（中转站枢纽折扣）

### 1.1 机制

- **判定**：星→地 **forward 航线段**（两端天体实时位连线）距任一 **中转站（relay 类型）** 实时位（`buildingPos`，含入轨公转）≤ `B.hubRelayRadius`（默认 300px）→ 该线**往返油耗 ×`B.hubRelayDiscount`**（默认 0.8，即 −20%）。
- **多站命中取最优，不叠加**：两座站都在带内仍单份折扣（`min` 聚合），防"贴两站=打四折"死平解。
- **仅 forward 生效**：中转链两段（relay_in/relay_out）与反向建材线的端点本来就是站，不重复打折。
- **实时判定**：`buildingPos` 随放置/公转变化，出发（`departShip` 锁定 `roundFuel`）与展示（`routeNetPerTrip`）各自判定；站拆了折扣即消失，已出发航段的油耗不回溯（出发时锁定口径与引力窗口一致）。
- **放置位即策略**：把中转站摆进木卫二/火星线沿线 = 给该线长期减负；摆两站无收益 → 站位唯一最优，拓扑决策成立。

### 1.2 口径咬合

| 系统 | 关系 |
|----|----|
| 引力窗口（模块 06） | 叠乘：窗口油耗 ×0.5 再 ×0.8。注意 `B.convoyFuelFloor` 封底只护窗口分量，借站折扣乘在其外——"窗口+借站"是全速减负组合技（有意保留） |
| 船级油耗（模块 05/副油箱） | 叠乘在 `roundFuel` 内，借站折扣乘在其外，互不干扰 |
| 净补入账（模块 01） | `completeUnload` 的 `net = cargo − roundFuel` 自动吃折扣，账本/统计零改动 |
| 供给速率/HUD | `supplyRateOf`/`estimateNetFlow` 走 `routeNetPerTrip`，折扣自动进展示口径 |
| 拖线浮层 | `forwardLabel` 用 `hubRelayMultForSegment` 实时预览折后油耗，命中时尾缀「借站补给」 |

### 1.3 提示与日志

- 每航线**首次**吃折扣：hint「航线途经中转站 · 借站补给接力，油耗打折」+ `logger.info`；删线清提示沿（重建重提示），不刷屏。
- 单测锁：`tests/warmPortHub.test.ts` 借站补给组。

## 2. 地球港泊位（节点吞吐上限）

### 2.1 机制

- **泊位数**：`B.portBerths`（默认 2，`global.config` 可覆盖）。**卸货占泊**：一艘船在地球卸货（`unloading` 状态）即占一个泊位，占用时长 = 卸货时长 `B.unloadSeconds × workMult`——**装卸速率旋钮（快速货泵/调度中枢）同时就是泊位周转率旋钮**。
- **满泊排队**：到港船（flying 抵达地球端）若泊位已满，**原地待命**（`SimShip.waitPort` 记到达时间，光点停在地球），泊位结算按 **FIFO**（同帧到达按船 id 稳定排序）放行。
- **放行唯一口**：到港分支只记时间不放行；`tickBerthQueue`（`tickShips` 每帧首）是唯一入卸货口——单写者，无竞态，快照/读档天然一致（占用 = 派生值，无独立容器，`waitPort` 旧档缺失 = 未排队，无迁移）。
- **占泊范围**：forward 星→地、relay_out 出站回运、火星模块任务返航（计时用 `moduleUnloadSeconds`）——**卸货点=地球的都占泊**；relay_in 入站与反向建材线卸在建筑端点，**不占泊**。
- **N 船 ≠ N 倍收益**：同线堆船超过泊位周转率后多出的船全在排队——运力上限 = `泊位数 × 泊位周转率`，船队分配从"越多越好"变成"远线近线争泊"的真调度题，并与造船上限（聚能环等级 ship_cap）形成两级容量墙。

### 2.2 耀斑/召回/删线咬合

- 耀斑冻结：排队船（flying 待泊）照常走 `resolveFlareDamage` 分区结算（地月系风暴照样冻港外船）；护盾存活恢复延迟（`resumeDelay`）期间不参与放行。
- 召回：排队船被召回（`recalling`）仍会按序靠泊卸完货再退役——**不丢货**语义不变。
- 删线：在途/排队船就近返航卸货，行为与旧口径一致。

### 2.3 可见性

- 到港/靠泊每次 `logger.info`（泊位占用、排队位次、余排队数）；满泊首次发 hint「地球港泊位已满（N）· 到港船只排队等待卸货」，清队复位沿。
- **V1.1 待办**：航线面板行加"排队 N"计数、星图待命光点呼吸标记（本期以日志+hint 承载可见性）。

## 3. 数值与配置

| 键 | 默认 | 说明 | 覆盖 |
|----|------|------|------|
| `B.portBerths` | 2 | 地球港泊位数 | `warm-current.global` 键 `portBerths` |
| `B.hubRelayRadius` | 300 | 借站判定半径（画布 px） | 键 `hubRelayRadius` |
| `B.hubRelayDiscount` | 0.8 | 借站油耗乘区（<1 生效） | 键 `hubRelayDiscount` |

数值均为首版占位，待试玩平衡（折扣与"引擎超频 −15%"同档；半径约等于地月距的 1/4，保证"摆在沿线"而非"贴着星"）。

## 5. 已定 / 待确认

- **（已定 2026-09-27）** 两机制本期实装；折扣不叠加、仅 relay 类型、仅 forward；泊位只做地球卸货端、排队 FIFO、无独立状态容器；可视线/排队计数 UI 缓一期。
- **（待确认）** 弧线穿罩（路径暴露代价）、线级优先级/配给、装矿速率（星端装载泊位）、折扣需站内有 H3 缓存（喂站博弈）、多站折扣递进表——按试玩反馈排队。
- **（待确认）** 数值：`portBerths=2` 开局是否过紧（月球线单船不受影响，第 3 艘船起排队）、`discount=0.8` 是否足以把木卫二直线拉平中转链。

## 6. 与其他模块的交互

- → 模块 01：折后净补入账（口径在 `completeUnload` 不变，自动生效）。
- → 模块 02：到港分流是 §3 飞船状态机的扩展（flying 到港 → unloading 之间插入泊位闸门）。
- → 模块 05：workMult（货泵/调度中枢）= 泊位周转率旋钮。
- → 模块 06：窗口与借站叠乘（见 §1.2）。
- → 模块 07：排队船照常参与耀斑分区结算。
- → 模块 11：中转站新增"补给枢纽"角色——放置价值 = 缓存建材 + 借站折扣二合一。
