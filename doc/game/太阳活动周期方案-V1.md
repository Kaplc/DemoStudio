# 太阳活动周期方案 V1.2（对手 = 太阳 · 冰汽时代式读条 + 日冕云团）

> **一句话定位**：把耀斑从"随机税"升级为"可读的对手"——按**行星系分区**（地月系 / 火星系 / 木星系，未来可扩恒星系），每区独立运转 平静 / 逼近 / 风暴 相位机、独立排定风暴；风暴排定即有**日冕云团从太阳飞向该区**（世界内的倒计时），右上角常驻冰汽时代式风暴读条（每区一条）与云团同源同步；风暴只冻结该区在途航线，多区错峰逼玩家做连续的运力调度取舍。
> **什么时候会用到你**：实施本方案时；排查分区相位 / 风暴读条 / 云团 VFX / 分区冻毁结算相关回归时；调各区相位时长、连发数、强度数值时。
> **状态**：**待实施**（2026-09-12 提案 V1；同日用户两轮定调：V1.1 冰汽时代暴风雪读条 + 每个行星系单独计算；V1.2 耀斑需有从太阳飞来的可视化云团——均已并入。背景：用户评估游戏"没什么博弈感"，本方案是"对手-代价-资源"博弈三角的第一格，与"稀缺压贴零"组合打底）。
> **设计理念**：冰汽时代的暴风雪从不搞突然袭击——读条常驻、时刻确定，恐惧随读条增长，准备围着读条展开。对手可读才有博弈；风暴分区化后，对手从一个变成一排，运力永远在"哪边安全往哪边跑"里打转。太阳不是敌人，是必须学会共处的天气。

## 1. 病根：现状为什么构不成博弈

| 现状机制（现行实现） | 为什么不是博弈 |
|---|---|
| 耀斑 `minInterval/maxInterval 100~150s` 随机降临（`events.config.json`） | 纯反应税：玩家无法规划，只能挨打后框选避难 |
| `warnLead = 10s` 预警（且需 `event_warning` 卡解锁） | 信息是开关不是光谱：无卡=零预警，有卡=固定 10s，没有中间态 |
| 引力窗口 `period 90s` 固定循环 | 节拍器：到点开窗，发船不需要任何判断 |
| 耀斑全局结算（`resolveFlareDamage` 冻结全部在途船） | 全局天灾没有避风港，也造不出"哪边安全跑哪边"的调度决策 |
| 冻毁损失只有"框选避难"一层决策 | 缺少"何时备、备多少、往哪区备"的上层博弈 |

## 2. 核心设计：分区相位机 + 冰汽时代式读条

### 2.1 行星系分区（每区独立计算）

| 分区 | 成员天体 | 对应产线 | 解锁幕次 | 风暴性格 |
|---|---|---|---|---|
| 地月系 | earth + moon | 一幕月球线 | 第一幕 | 频繁但温和（I~II 级） |
| 木星系 | jupiter + europa | 二幕木卫二线 | 第二幕 | 低频但凶猛（II~III 级） |
| 火星系 | mars | 三幕环扩展线 | 第三幕 | 中频且渐强（I~III，III 权重随幕次涨） |
| 水星 | mercury | 金属矿线（建材） | 第一幕，**无风暴** | 安全区（远距离油耗即其代价） |

- **分区 = 配置表驱动**（`star_map.config` 或独立 `solar_zones` 段声明成员天体），未来加恒星系 = 加一个 sun 键、一组区——"每个行星系单独计算"在架构上无条件成立。
- **分区随产线解锁**：每幕的新航线自带新天气，风暴机制本身成为三幕教学的载体（一幕用地月系温和风暴学会读条备船）。
- 每区独立跑 相静/活跃/风暴 相位机（半马尔可夫），**各区相位错峰**（开局时预掷错开，不各自从 calm 起点同步起跑）。

### 2.2 相位机（区内，每区独立）

| 相位 | 时长（秒） | 行为 |
|---|---|---|
| 平静 | 50~80 | 无风暴；该区回血窗口 |
| 逼近（云团在途） | 30~50 | **日冕云团已从日面隆起飞出**，沿日-区走廊飞向该区（见 §3.1）——云团在途时间 = 本相时长，抵达即爆发；右上角读条同步切为逼近倒计时 |
| 风暴 | 25~40 | 耀斑连发 1~2 发（发波间隔 = 上一发 duration + 8s），只冻结该区在途航线 |

- **风暴时刻提前排定**：区转入逼近相时即预掷风暴时刻与强度（deterministic，读条与云团共同可信）——这是冰汽时代读条的精髓：可预读、可备战，恐惧来自逼近而不是惊吓。云团在途时长 = 逼近相时长，**看云团飞到哪 = 读进度条**。
- **分区冻毁**：耀斑只结算风暴区的在途船；其他区照常运转。**"哪边安全往哪边跑"**成为常态调度：地月系风暴时集中运力跑木卫二（若其 calm），反之亦然。
- **引力窗口 × 木星系风暴**：窗口仍全局周期，但木星系风暴期该线实质不可用（发船=送冻）——窗口与风暴读条对表成为二幕核心操作。

## 3. 右上角读条组（信息主载体）

参考冰汽时代暴风雪读条，右上角**每区一条、竖排堆叠**（区数 = 条数，首版最多 3 条活跃区）：

| 读条状态 | 显示 |
|---|---|
| 平静 | 灰蓝色，平静相剩余进度；该区名 + "平静" |
| 逼近（活跃） | 逐步转橙红，显示风暴逼近倒计时读条；临近 10s 泛红脉动 |
| 风暴中 | 炽红，风暴持续进度 + 剩余发数 |
| 未解锁区 | 不显示 |

- **读条免费、常驻、可信**——时机信息不再收费，也不再有"无卡全盲"状态（废除现行 `flareWarning` 开关门）。
- **`event_warning` 卡改语义为"强度精报"**：读条只告诉你**何时**来，精报告诉你**几级**（III 级 duration 30s、连发概率翻倍——囤多少防冻由强度决定）。订阅开关 1 H3/s，与造船/研究/环建争夺同一份家底。信息经济保留，但从"买时机"改为"买烈度"。

### 3.1 日冕云团：读条的世界内化身

读条是给对局者的报表，云团是给眼睛的天气——两者同源（同一个 `stormAt` 驱动），玩家任选其一读取进度：

- **起飞预兆（-3s）**：云团起飞前 3 秒，日面朝向目标区一侧隆起一个亮斑（日冕物质抛射的蓄力读），配低频预警音——余光就能察觉"那边要出事了"。
- **在途飞行**：云团为**定向走廊状湍流云**（非全向环带），从日面沿直线走廊飞向目标区中心。走廊定向是有意为之：全向环带会产生"路过水星为什么没事"的误读，走廊则一眼读出"这团是冲木星系去的"。位置 = `lerp(日面出发点, 区中心, t)`，t 由逼近相进度驱动。
- **抵达爆发**：云团在区中心扩散炸开（additive 辉光 + 轻屏震 + 警报音），区内空间泛红直至风暴结束；爆发瞬间触发该区第一发耀斑。
- **多区并发**：各云团独立飞行互不干扰，走廊方向即目的地标识；两团同时在途时，读条组与星图云团一一对应（顺序一致，颜色区分可选）。
- **管线复用（零新造轮子）**：云团贴图走既有 4k 云图柔化管线（灰度×alpha，群星观感改版已验证）+ engine CPU 粒子 + additive 辉光；屏震用 engine 屏震组件；音效走 `audio.ts` 既有总线与耀斑警报共用通道。

## 4. 决策空间：错峰调度三笔账

1. **跨区调度账**：两条线的风暴错峰时，运力永远在做"现在把船压到哪条线"的再平衡——这是分区化带来的最大新增博弈，也是治愈感的安全阀（总有安全区可去，但要去就有成本：改线、油耗、装卸）。
2. **时机账**：木星系读条逼近时，在途的木卫二船撤不撤（靠站避难 vs 照跑赌 I 级）、窗口发不发新船。
3. **防冻账**：加热器（320 H3/件）按区配比——地月系可裸奔，木星系常备；精报准就按需囤，不订就超额保险。**护盾地理分层**：护盾罩（地球轨道背日半圆）只救得到地月系风暴的船；外区风暴想靠护盾，得在木星/火星轨道布防盾建筑（轨道建筑可部署性见 §8 开放问题）——护盾从"地球专属"升格为"各系布防"的基建决策。

与现有框选决策的分工：**分区层决定"往哪跑"，读条层决定"何时备"，框选层决定"谁去哪"**——三层叠加才是完整的博弈结构，现行实现只有最后一层。

## 5. 玩家循环

```
扫右上角读条组 → 地月系逼近、木星系平静 → 运力压向木卫二线
    →（怕 III 级？开精报订阅 1 H3/s）→ 风暴降临：该区在途船框选决策（现有）
    → 风暴过：读条转灰蓝，运力回流该区 → 下一轮错峰
```

## 6. 数值草案（`events.config.json` 重构为分区段）

```jsonc
"solar": {
  "zones": {
    "earthmoon": { "members": ["earth", "moon"], "act": 1, "intensity": [0.6, 0.4, 0.0] },
    "jupiter":   { "members": ["jupiter", "europa"], "act": 2, "intensity": [0.0, 0.5, 0.5] },
    "mars":      { "members": ["mars"], "act": 3, "intensity": [0.3, 0.35, 0.35] }
  },
  "phase": { "calm": [50, 80], "active": [30, 50], "storm": [25, 40], "flares": [1, 2], "flareGap": 8 },
  "transition": { "calmToActive": 0.7, "activeToStorm": 1.0 },
  "intensityDuration": { "I": 20, "II": 25, "III": 30 }
}
```

- 活跃相（展示名"逼近"，配置键保留 `active`）结束时**必转风暴**（`activeToStorm: 1.0`）——读条与云团因此可信：逼近读条读满 / 云团抵达必爆，冰汽时代同款确定性；随机性全部前移到"平静何时结束、风暴几级、连发几发"。
- 现有 `flare.minInterval/maxInterval/firstDelay/warnLead` 废弃；`duration` 保留为 I 级基础值。

## 8. 开放问题（默认值待拍板）

- **护盾外区部署**：轨道建筑（`orbit_build`）是否放开木星/火星轨道建盾？默认建议：放开但造价 ×1.5（外线基建税），护盾地理分层才有解法。
- **精报置信**：读条时机已免费确定，精报强度首版 100% 还是带噪？默认建议：100%（付费买的是规划确定性，不是赌博筹码），试玩后再议加噪。
- **风暴期间引力窗口是否硬冻结**：V1 的"计时冻结顺延"在分区制下简化为——窗口照常开，但木星系风暴期开窗无船敢用；不再需要特判冻结规则。默认采纳简化案。
- **第三幕"超级风暴"**：火星系 III 权重是否在环扩展模块运输途中临时拉满（终局压力源，与全球环网任务线叠加）？
- **读条组视觉**：三区读条与堆心温度主指标同屏，右上角堆叠是否挤压星图视野；风暴区在星图内的范围指示（区边界光晕？）需要美术定调。
- **云团在途时长是否按轨道距离缩放**：物理上更远的区预警更长（地月系短促被动、木星系充裕从容，顺带放大长航程撞团的概率差）；默认建议首版全区统一 30~50s，试玩后再评估距离缩放。

## 9. 与"稀缺压贴零"的协同（博弈三角的拼法）

- 本案给**对手**（一排分区风暴 + 可预读读条），稀缺案给**代价**（家底贴零时冻一艘船 = 真失血）——两者相乘才出博弈感，单独上线各自都弱。
- 实施顺序：本案先行（不依赖数值收紧，可独立验证），稀缺案随后只动 `balance.ts` 与 `level_burn` 曲线。
- 第三格候选：**矿脉枯竭节拍**（压 `mineral_deposit.table.json` 储量至对应幕枯竭 + 限时富矿彗星），凑齐"对手-代价-资源"三角后再评估构筑取舍（环建筑互斥）是否还需要。
