# 游戏 UI 设计

## 设计模式


---
  #### **名称**
Diegetic（融入世界）UI 集成
  #### **描述**
将 UI 元素嵌入游戏世界内部，以获得最大程度的沉浸感
  #### **适用时机**
为沉浸式体验设计 UI 时——打破第四面墙会损害代入感
  #### **示例**
    Diegetic UI 示例：
    - 生命值显示在角色背部的显示屏上（《死亡空间》)
    - 弹药计数器在武器本体上（《光环》)
    - 地图是角色手中拿着的实体物品（《孤岛惊魂 2》)
    - 任务标记直接放在世界里而非小地图（《旷野之息》)
    - 用收音机/手机接收任务目标（GTA 系列）
    
    实现注意事项：
    - 游戏过程中必须保持可读
    - 需要无障碍后备方案
    - 相机角度会影响可见性
    - 3D UI 元素有性能成本
    
    何时不要用：
    - 速度至上的竞技游戏
    - 信息会被频繁查阅的场合
    - 复杂、数据繁重的游戏（RPG）
    

---
  #### **名称**
上下文相关 HUD 可见性
  #### **描述**
只在相关信息出现时显示 UI 元素，在探索/过场动画时隐藏它们
  #### **适用时机**
在信息展示与视觉沉浸感之间取得平衡
  #### **示例**
    可见性状态：
    1. 隐藏：探索、过场动画、拍照模式期间
    2. 闪现：相关动作发生时短暂出现
    3. 常驻：始终可见（战斗中的生命值）
    4. 展开：按需显示完整细节（按住按钮）
    
    触发示例：
    - 血条：满血时隐藏，受伤时出现，5 秒后淡出
    - 弹药：切换武器/换弹/弹药不足时出现
    - 小地图：安全区隐藏，危险区可见
    - 任务目标：按钮切换，战斗时自动隐藏
    
    淡入淡出时机：
    - 关键信息立即出现（0ms）
    - 常规元素快速淡入（150ms）
    - 慢速淡出（500ms）避免突兀消失
    - 自动隐藏前的保持阈值（2s）
    

---
  #### **名称**
安全区实现
  #### **描述**
将关键 UI 限制在电视/显示器安全区内，防止被裁切
  #### **适用时机**
为主机游戏或任何在多种显示器上运行的游戏设计时
  #### **示例**
    安全区标准：
    - 动作安全区：屏幕的 93%（外侧 3.5% 可能被裁切）
    - 标题安全区：屏幕的 90%（外侧 5% 不可靠）
    - 现代电视：通常显示完整画面，但请假定它们不会
    
    实现：
    ┌─────────────────────────────────────┐
    │  ┌─────────────────────────────┐    │
    │  │  关键 UI（血条、弹药）      │    │ <- 标题安全区 (90%)
    │  │  ┌─────────────────────┐    │    │
    │  │  │   游戏内容          │    │    │ <- 动作安全区 (93%)
    │  │  └─────────────────────┘    │    │
    │  └─────────────────────────────┘    │
    └─────────────────────────────────────┘
    
    允许玩家自行调整：
    - 选项中的安全区滑条
    - 校准用的测试图案
    - 按显示器记住设置
    

---
  #### **名称**
手柄优先的导航设计
  #### **描述**
先为手柄设计菜单导航，再考虑鼠标，确保没有指针也能完整操作
  #### **适用时机**
任何支持手柄的游戏或主机版本
  #### **示例**
    手柄导航原则：
    1. 方向键在元素间导航
    2. 清晰的视觉焦点指示（不只是颜色变化）
    3. 逻辑流向（从左到右、从上到下）
    4. 循环导航（行末跳到下一行开头）
    5. 返回菜单时记住上次位置
    
    焦点指示要求：
    - 高对比边框/辉光（不只是高亮）
    - 用动画吸引注意力
    - 在所有背景上都可见
    - 色盲用户也能看清
    
    按键映射：
    - A/X：确认、选择
    - B/圆圈：返回、取消
    - 肩键/扳机键：标签页切换、分类导航
    - Start：暂停菜单
    - Select/Back：次要菜单、地图
    
    导航网格示例：
    [背包] [地图] [任务] [选项]
      ↓     ↓      ↓        ↓
    用 LB/RB 切换标签页
    

---
  #### **名称**
高动态下的可读性
  #### **描述**
确保 UI 在镜头抖动、特效和快速移动的激烈战斗中仍然可读
  #### **适用时机**
为动作游戏、FPS、赛车或任何高动态玩法设计 HUD 时
  #### **示例**
    可读性技巧：
    
    1. 对比背景：
       ┌──────────────────────┐
       │ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │  <- 深色容器
       │ ▓  生命值: 85/100  ▓ │  <- 浅色文字
       │ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │
       └──────────────────────┘
    
    2. 文字描边/阴影：
       - 2px 对比色描边
       - 投影增加层次
       - 两者结合获得最大可读性
    
    3. 稳定的锚点：
       - HUD 元素固定在屏幕边缘
       - 游戏过程中尽量少动画
       - 镜头抖动时保持静止
    
    4. 尺寸阈值：
       - 正文文字在 1080p 下最小 14px
       - 关键信息（血条）最小 24px
       - 随分辨率缩放，不随视口缩放
    
    5. 带后备方案的颜色编码：
       - 红色表示危险 + 图标 + 标签
       - 绝不只用颜色（色盲用户）
    

---
  #### **名称**
渐进式信息披露
  #### **描述**
将信息从关键到详细分层呈现，按需揭示更多内容
  #### **适用时机**
设计背包、技能树或属性面板等复杂系统时
  #### **示例**
    信息层级：
    
    第 1 层 - 扫一眼（始终可见）：
    [剑图标] "铁剑"  攻击: 25
    
    第 2 层 - 悬停/聚焦（选中时）：
    [剑图标] "铁剑"
    攻击: 25  |  敏捷: +5  |  重量: 3.5
    "任何战士都信赖的可靠武器"
    
    第 3 层 - 检视（按键时）：
    完整属性对比、背景故事、升级路线、
    获得历史、耐久度、附魔
    
    实现：
    - 悬停 300ms 后出现提示框
    - "更多信息"按钮进入第 3 层
    - 手柄：A 键第 2 层，长按 A 第 3 层
    - 触控：轻点第 2 层，长按第 3 层
    

---
  #### **名称**
伤害数字设计
  #### **描述**
展示战斗反馈数字，既要传达信息又不能造成视觉杂乱
  #### **适用时机**
为 RPG、动作游戏或任何带数值伤害的战斗系统设计反馈时
  #### **示例**
    伤害数字最佳实践：
    
    1. 按类型区分：
       - 普通伤害：白色、标准大小
       - 暴击：黄色、150% 大小、抖动
       - 元素伤害：带颜色（火=橙色、冰=蓝色）
       - 治疗：绿色、向上飘浮
       - 格挡/抵抗：灰色、更小
    
    2. 动画模式：
       - 向上飘浮并淡出（经典）
       - 弹出并缩小（有冲击力）
       - 累积后爆发（连击）
       - 老虎机式滚动（期待感）
    
    3. 聚合提高可读性：
       - 将快速连击合并为单个数字
       - 显示 "12 + 12 + 12" 然后 "总计 36"
       - 垂直堆叠，最新的在最上
       - 同时最多 5-6 个可见
    
    4. 性能考虑：
       - 对象池化伤害数字
       - 限制每个数字的粒子效果
       - 大规模战斗中降低频率
    

---
  #### **名称**
环形菜单设计
  #### **描述**
创建高效的环形/转盘菜单，便于手柄或鼠标快速选择
  #### **适用时机**
武器、技能、表情或指令的快速访问菜单
  #### **示例**
    环形菜单原则：
    
    1. 分段数量：
       - 4 段：只有四个方向
       - 8 段：手柄的最优选择
       - 12 段：舒适上限
       - 超过 12 段：使用嵌套环
    
    2. 布局：
       ┌─────────────────┐
       │       北        │
       │    ┌─────┐      │
       │  西 │     │ 东   │  8 方向环
       │    └─────┘      │  摇杆方向 = 选择
       │       南        │
       └─────────────────┘
    
    3. 交互模式：
       - 按住打开，松开选择
       - 切换打开，确认选择
       - 甩动手势（进阶）
    
    4. 视觉反馈：
       - 选中段高亮
       - 悬停时图标放大
       - 确认前预览选择
       - 最近使用/常用项放在顺手位置（东、北）
    
    5. 时间减速：
       - 菜单打开时可选择慢动作
       - 保持游戏流畅感
       - 不适合多人/竞技游戏
    

---
  #### **名称**
冷却指示器设计
  #### **描述**
清晰地传达技能可用性与计时状态
  #### **适用时机**
设计技能栏、技能冷却或任何基于时间的可用性时
  #### **示例**
    冷却可视化方法：
    
    1. 钟表扫过式：
       ┌───┐     ┌───┐     ┌───┐
       │░▓▓│  →  │░░▓│  →  │░░░│
       │▓▓▓│     │░▓▓│     │░░░│
       └───┘     └───┘     └───┘
       75% 冷却   50% 冷却   就绪！
    
    2. 填充条：
       [████░░░░░░] 40% 就绪
    
    3. 倒计时数字：
       技能图标叠加 "3.2" 数字
    
    4. 组合（最佳）：
       - 钟表扫过式做视觉
       - 数字叠加做精确
       - 就绪时闪烁/发光
       - 就绪时有音频提示
    
    需要设计的状态：
    - 冷却中（变暗、钟表扫过）
    - 即将就绪（轻微脉冲）
    - 就绪（全亮、可选辉光）
    - 使用中（高亮边框）
    - 禁用（置灰、X 叠加）
    

---
  #### **名称**
小地图最佳实践
  #### **描述**
设计既能辅助导航又不至于成为依赖的小地图
  #### **适用时机**
开放世界、探索类游戏，或任何需要空间感知的游戏
  #### **示例**
    小地图设计决策：
    
    1. 形状与位置：
       - 圆形：经典，适用于大多数游戏
       - 矩形：更适合网格世界
       - 仅指南针：最大沉浸感（《天际》)
       - 右上角：标准位置，避开主视线
       - 左下角：不常见，按游戏评估
    
    2. 信息层级：
       - 玩家（始终居中、清晰指示）
       - 目标（醒目、脉冲）
       - 敌人（红色、仅在侦测到时）
       - 友军（蓝/绿色）
       - 兴趣点（按类型区分图标）
       - 地形（低调、不能喧宾夺主）
    
    3. 旋转模式：
       - 北朝上：更容易对照地图
       - 玩家朝上：更容易辨别方向
       - 设置里让玩家自己选
    
    4. 缩放：
       - 默认缩放覆盖周围区域
       - 捏合/滚轮缩放
       - 快速旅行/载具时自动缩放
    
    5. 战争迷雾：
       - 未探索区域变暗
       - 到访后揭示
       - 可选：随时间重新迷雾
    

---
  #### **名称**
按键提示适配
  #### **描述**
根据当前使用的手柄类型动态显示正确的输入提示
  #### **适用时机**
任何支持多种输入方式的游戏（键盘、手柄、触控）
  #### **示例**
    输入检测与显示：
    
    1. 检测输入方式：
       - 最近使用的输入决定提示
       - 新输入类型即时切换
       - 宽限期防止闪烁
    
    2. 平台专属图标：
       Xbox：    [A] [B] [X] [Y] [LB] [RB]
       PS：      [X] [O] [□] [△] [L1] [R1]
       Switch：  [A] [B] [X] [Y] [L] [R]
       键盘：    [空格] [E] [Tab] [Shift]
       触控：    [轻点] [长按] [滑动]
    
    3. 改键支持：
       - 显示当前绑定键，而非默认键
       - 内部用 "[主行动]" 而非 "[A]"
       - 改键后更新提示
    
    4. 提示位置：
       - 情境提示靠近交互点
       - 教程提示屏幕中央
       - HUD 提示在固定位置
    
    5. 动词优先设计：
       "按 [A] 打开" 比 "[A] 打开"
       对新玩家更清晰
    

---
  #### **名称**
通知队列管理
  #### **描述**
在不压垮玩家的前提下处理大量通知
  #### **适用时机**
有成就、掉落、任务更新或任何高频通知的游戏
  #### **示例**
    通知系统设计：
    
    1. 优先级：
       - 关键：立即、打断（低血量警告）
       - 高：队列中的下一个（任务完成）
       - 普通：标准队列（成就）
       - 低：合并处理（材料 ×5）
    
    2. 队列行为：
       - 同时最多 2-3 条可见
       - 新通知把旧的顶上去/挤掉
       - 关键通知绕过队列
       - 玩家可提前关闭
    
    3. 显示时机：
       - 出现：200ms 滑入
       - 停留：按内容 3-5 秒
       - 消失：300ms 淡出/滑出
       - 队列间隔：通知间 500ms
    
    4. 合并：
       "金币 +50" + "金币 +30" = "金币 +80"
       只合并同类型
       重复物品显示 "×5"
    
    5. 历史记录：
       - 菜单中的通知日志
       - 最近通知回顾按钮
       - 绝不丢失重要信息
    

## 反模式


---
  #### **名称**
杂乱无章的 HUD
  #### **描述**
无论相关性如何，始终显示所有可能的信息
  #### **为什么**
    压垮玩家、降低沉浸感、把关键信息埋没在噪音里。
    屏幕空间是从游戏世界借来的——每个元素都有代价。
    
  #### **应该这样做**
    上下文相关可见性：
    - 血条：仅受伤时显示
    - 弹药：仅掏武器时显示
    - 小地图：仅危险区域显示
    - 任务追踪：可开关
    
    对每个元素都要问："玩家现在就需要这个吗？"
    如果现在不需要，就隐藏它或让它按需可访问。
    

---
  #### **名称**
UI 遮挡行动
  #### **描述**
菜单或 UI 元素遮挡了重要的游戏区域
  #### **为什么**
    玩家会死在看不见的敌人手里。不暂停的背包界面让玩家暴露在危险中。
    战斗期间关键信息藏在提示框后面。
    
  #### **应该这样做**
    安全定位：
    - 全屏菜单暂停游戏（或提供选项）
    - 提示框远离准星
    - 快捷菜单放角落，不放中央
    - 非关键 UI 使用透明背景
    - "战斗模式"隐藏非必要 UI
    

---
  #### **名称**
仅鼠标导航
  #### **描述**
菜单必须用鼠标/触控操作，无法用手柄导航
  #### **为什么**
    完全排除手柄玩家。很多 PC 玩家也偏好手柄。
    主机移植变得不可能。这是无障碍失败。
    
  #### **应该这样做**
    手柄优先设计：
    - 在指针之前设计网格导航
    - 每个元素必须可聚焦
    - 每个操作必须有按键等价物
    - 仅用手柄测试完整流程
    

---
  #### **名称**
过小的触控目标
  #### **描述**
按钮和交互元素太小，无法可靠触控或手柄选择
  #### **为什么**
    误触让玩家恼火。小目标是无障碍失败。
    移动端玩家手指大小不一。手柄选择框需要内边距。
    
  #### **应该这样做**
    尺寸指南：
    - 触控：最小 44x44pt（Apple）、48x48dp（Google）
    - 手柄：选择框大于可见元素
    - 目标间留间距防止误选
    - 重要操作需要更大的目标
    

---
  #### **名称**
仅用颜色传达信息
  #### **描述**
把颜色作为重要游戏信息的唯一区分手段
  #### **为什么**
    8% 的男性有色觉缺陷。对他们来说游戏变得不可玩。
    红/绿区分失败最常见——而游戏恰好用它们区分敌/友。
    
  #### **应该这样做**
    冗余编码：
    - 颜色 + 形状：红色三角危险、绿色圆形安全
    - 颜色 + 图标：元素伤害配元素图标
    - 颜色 + 标签："致命"文字配红色样式
    - 色盲模式：红色盲、绿色盲、蓝黄色盲选项
    

---
  #### **名称**
分辨率相关的尺寸
  #### **描述**
UI 元素用绝对像素定尺寸，不随分辨率缩放
  #### **为什么**
    1080p 显示器上可玩，4K 电视上微观，720p 掌机上巨大。
    现代游戏运行在差异极大的显示尺寸和观看距离上。
    
  #### **应该这样做**
    响应式缩放：
    - 以 1080p 为基准设计
    - 所有元素按比例缩放
    - 提供 UI 缩放滑条（50% - 200%）
    - 在 720p、1080p、1440p、4K 上测试
    - 考虑观看距离（电视 vs 显示器 vs 掌机）
    

---
  #### **名称**
游戏进行中无法获取关键信息
  #### **描述**
关键信息只能通过暂停或打开菜单才能看到
  #### **为什么**
    为了看状态而打断节奏很恼火。玩家不应该需要
    暂停才知道自己的血量、弹药或任务目标。依赖暂停菜单的设计是坏味道。
    
  #### **应该这样做**
    可一瞥而见的关键信息：
    - 血条/护盾始终可访问（哪怕是最小化）
    - 当前目标一键可达
    - 掏枪时显示弹药
    - 状态效果显示在角色或 HUD 上

  #### **名称**
不一致的按键映射
  #### **描述**
不同菜单中同一按键做不同的事，且没有清晰提示
  #### **为什么**
    "B"在一个菜单是返回、另一个是取消、第三个是丢弃物品。
    玩家靠肌肉记忆——不一致会造成失误和挫败。
    
  #### **应该这样做**
    一致的映射规则：
    - A/X：始终确认/选择
    - B/圆圈：始终返回/取消
    - 记录并显示当前映射
    - 如果语境改变行为，显示提示
